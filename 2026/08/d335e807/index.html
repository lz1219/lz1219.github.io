上下文工程（三）：记忆系统实战——给 Agent 装上外存

发表于2026-08-14|更新于2026-08-14|技术
|浏览量:

上下文窗口再大，会话一结束就清零——这是 Agent 的”失忆症”。2025 年底以来，记忆系统从研究配角升格为一等工程问题：47 位作者的联合综述甚至断言”传统记忆分类学对 AI Agent 已经不够用”。但 2026 年的基准测试同时揭示了一个残酷真相：记忆系统用不好，比没有更糟。 本文把前沿格局和落地做法一次讲清。

一、先分清三件事：上下文、RAG、记忆

这三个概念经常被混用，但它们的机制完全不同：

机制 存什么 生命周期 类比
上下文窗口 当前任务的临时信息 单次会话 工作台
RAG 静态的外部文档 只读 图书馆
记忆系统 交互中学到的东西 跨会话、可读写、可演化 大脑的海马体 + 皮层

记忆系统的独特价值在于第三点：它存的不是”资料”，而是经验——上次这么改失败了、用户偏好 tabs 缩进、这个模块的测试必须用特殊命令。这些信息在任何文档里都不存在，只能从交互中习得，也最容易在会话结束时丢失。

二、前沿格局：2023–2026 记忆系统演进地图

奠基：MemGPT / Letta（2023）——操作系统的隐喻

MemGPT（arXiv 2310.08560，ICLR 2024）开创性地把 LLM 记忆管理类比为操作系统虚拟内存：

  • Core memory（核心记忆）：驻留上下文内，类比 RAM——当前任务的关键状态；
  • Recall memory（回忆记忆）：完整对话历史，类比磁盘；
  • Archival memory（归档记忆）：外部数据库，模型用”分页”机制主动在主上下文与外部存储之间搬运数据。

2025 年其延续项目 Letta 引入 sleep-time compute：把记忆整理从对话时间剥离，让 Agent 在”空闲时”异步巩固记忆——很像人类睡眠中的记忆固化。2026 年 2 月，Letta 又推出 Context Repositories：用 Git 做版本化记忆后端，记忆变更可 diff、可回滚。

工业化：Mem0（2025）——两阶段流水线

Mem0 把记忆做成轻量可嵌入的层：提取 → 更新两阶段——LLM 从对话中抽取候选事实，再与向量库中的既有记忆对账（ADD / UPDATE / DELETE / NOOP 四选一）。在 LOCOMO 基准上比 OpenAI 官方记忆准确率高出 26%；图变体 Mem0g 用有向标记图存储实体关系。

自组织：A-MEM（2025，NeurIPS）——卡片盒笔记法

A-MEM（arXiv 2502.12110）借鉴 Zettelkasten（卡片盒笔记法）：每条记忆被自动标注标签、关键词和上下文描述，并动态链接到相关历史记忆；新证据到来时，旧记忆会被改写、链接会演化。记忆从”追加式日志”变成了”可编辑的知识网络”。

其他值得知道的流派

  • MemoryBank：用艾宾浩斯遗忘曲线建模记忆的时间衰减与强化；
  • Zep / Graphiti：在向量检索之上叠加时序知识图谱，优化跨会话的时间推理；
  • Generative Agents：周期性地让 LLM 对记忆流做反思（reflection），从观察中提炼高层结论；
  • ACE（本系列第一篇讲过的 ICLR 2026 工作）：Agent 记忆即不断进化的 Playbook，用增量 delta 更新对抗上下文坍塌。

产品化标杆：Anthropic 的组合拳

最值得参考的生产级实现，是把记忆拆成三个协同的部件：

  1. Memory tool：给模型对 /memories 目录的文件级操作（增删改查），记忆以纯文件形式存在、跨会话存活——结合 context editing 后 agentic search 性能提升 39%；
  2. Context editing：接近窗口上限时自动清理陈旧工具结果，100 轮任务 token 消耗降低 84%；
  3. 结构化笔记：Agent 在工作区维护 NOTES.md / todo 文件，记录进度、已确认的事实、未决问题，压缩或重启后重读恢复状态。

注意这三者的分工：压缩管”会话内不溢出”，笔记管”会话内可恢复”，memory tool 管”跨会话不遗忘”。

三、冷水时间：2026 年基准揭示的四个残酷真相

记忆系统不是免费午餐。今年上半年的系统性评测给出了必须知道的反直觉结论：

  1. 外部记忆可能拖累性能。MemoryArena 基准（2026）以任务完成率（而非检索准确率）为指标，发现某些场景下引入外部记忆反而降低表现——检索回来的无关记忆就是 Context Rot 里的干扰项。
  2. 写入路径是隐藏成本黑洞。实测 profiling 显示：记忆操作可消耗 Agent 总执行时间的 80% 以上；一套 500 段对话的事实提取，在回答第一个用户问题之前就要烧掉 1.6 亿 token。只看准确率的评测完全看不见这笔账。
  3. 错误记忆会自我繁殖。错误信息一旦入库，就会在后续交互中被反复检索、反复引用（Context Poisoning 的跨会话版）。而且现有系统不区分”已验证的事实”和”未验证的猜测”——记忆里没有置信度概念。
  4. 遗忘比记住更难。在专门测试”该忘的能不能忘掉”的 ForgetEval-Adv 上（385 个用例），主流系统的严格通过率只有 52.7%（Letta）到 70.6%（A-MEM）——过期记忆、冲突记忆（MemConflict 基准专门考这个）是普遍短板。

结论：记忆系统的瓶颈不在”读”，而在”写”。 写什么、谁来验证、什么时候删——这三个写入侧问题决定了系统是资产还是负债。

四、落地实战：个人与团队现在就能用的文件式记忆

不需要引入任何框架，用纯文件就能搭出 80% 的价值。按记忆类型分三层：

层 1：语义/程序性记忆 → AGENTS.md（永久的”怎么做事”）

详见本系列第二篇。它承载的是稳定不变的部分：构建命令、规范、红线、踩坑清单。

层 2：情景记忆 → 进度与决策文件（项目演进中的”发生了什么”）

在仓库里维护两个轻量文件：

决策日志是被严重低估的记忆类型——它记录的不是”代码现在是什么样”（代码自己会说话），而是”为什么变成这样”以及”曾经否决过什么“。Agent 没有它，就会反复提议你早已否决的方案。

层 3：跨项目偏好 → 用户级记忆文件

工具支持的话（如 ~/.claude/ 下的个人配置），存放与具体项目无关的偏好：沟通语言、代码风格口味、常用工作流。

写入侧的四条纪律（针对第三节的四个真相）

  1. 只写”验证了的事实”和”做过的决策”，不写猜测；拿不准的标注 [未验证]；
  2. 写入要克制：问自己”三个月后这条还有用吗”；临时调试信息留在会话里，不落盘；
  3. 定期遗忘：每月扫一次记忆文件，删掉已失效条目（记忆文件的腐化速度比代码快）；
  4. 用 Git 管理记忆文件：变更可审查、可回滚——这正是 Letta Context Repos 的思路，用 Git 原生能力就能免费获得。

五、什么时候才需要上”真”记忆框架

纯文件方案覆盖不了时（多用户个性化、海量记忆条目、需要语义检索），再考虑 Mem0 / Zep / Letta 这类系统。选型时问三个写入侧问题：

  • 写入成本多少？（提取要调几次 LLM？总执行时间占比？）
  • 冲突怎么解决？（新事实和旧记忆矛盾时，谁赢？）
  • 怎么删？（有没有 release/forget 原语？遗忘测试通过率多少？）
