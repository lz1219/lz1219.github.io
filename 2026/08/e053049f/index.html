Docker 常用命令与核心知识总结

容器化已经是后端开发和部署的标配。本文梳理 Docker 的日常命令、Compose 编排、网络模式、数据卷和 Dockerfile 编写要点，作为日常工作的速查手册。

一、三个核心概念

先理清三个概念，后面所有命令都围绕它们：

  • 镜像（Image）：只读的打包模板，包含应用代码、依赖和运行环境，类似”安装包”
  • 容器（Container）：镜像的运行实例，类似”安装后运行的程序”，可创建、启动、停止、删除
  • 仓库（Registry）：存放镜像的地方，Docker Hub 是官方公共仓库

关系一句话：从仓库拉取镜像，用镜像运行容器。

三、容器命令

3.1 运行容器

docker run 是最复杂的命令，记住常用参数即可：

参数 作用
-d 后台运行（detached）
-it 交互式 + 伪终端（调试时用，如 docker run -it ubuntu bash）
--name 指定容器名，方便后续操作
-p 宿主端口:容器端口 端口映射
-v 宿主路径:容器路径 挂载数据卷
-e KEY=VALUE 设置环境变量
--restart 重启策略：no / always / unless-stopped / on-failure
--network 指定网络模式
--rm 退出后自动删除（一次性任务用）

3.2 日常管理

四、网络模式

Docker 网络是容器通信的核心，共四种模式：

4.1 bridge（默认模式）

容器连接到虚拟网桥 docker0，各自分配独立 IP（默认 172.17.0.x 网段），通过 NAT 访问外网。外部访问容器必须做端口映射（-p）。同宿主机上大多数场景用这个。

4.2 host

容器直接使用宿主机网络，没有隔离，不需要端口映射，性能最好。但端口会冲突，一台机器只能跑一个占用 80 端口的容器。适合对网络性能敏感的场景。

4.3 none

容器没有任何网络，只有 lo 回环。用于完全隔离的场景（如处理敏感数据的批处理任务）。

4.4 container

新容器共享另一个已存在容器的网络栈，两者可通过 localhost 通信。Kubernetes 中 Pod 内多容器就是这个原理。

4.5 自定义网络：容器互访的正确姿势

默认 bridge 网络里容器只能用 IP 互访（IP 重启后会变）；自定义网络内置 DNS，可以用容器名互相访问，这是多容器应用的标准做法：

七、Dockerfile 编写要点

常用指令：

指令 作用
FROM 基础镜像，必须是第一条
WORKDIR 工作目录（后续指令的相对路径基准）
COPY / ADD 拷贝文件（ADD 支持解压 tar 和远程 URL，一般用 COPY）
RUN 构建时执行命令（装依赖等）
ENV 环境变量
EXPOSE 声明端口（仅文档作用，实际映射靠 -p）
CMD 默认启动命令（可被 run 参数覆盖）
ENTRYPOINT 固定入口（不易被覆盖，常与 CMD 搭配传参）

镜像分层：每条指令生成一层，层有缓存。优化技巧：

  • 变化少的指令放前面（依赖安装），代码 COPY 放最后，最大化利用缓存
  • 合并 RUN 指令减少层数：RUN apt update && apt install -y xxx && rm -rf /var/lib/apt/lists/*
  • 用 .dockerignore 排除 target/、.git/ 等无关文件
  • 编译型项目用多阶段构建，最终镜像只留产物：

八、清理与维护

长期运行的服务器建议定期 docker system prune，镜像层积累很容易把磁盘吃满。

总结

推荐的学习路径：

  1. 先用 run / ps / logs / exec 这组命令把常用中间件（Nginx、MySQL、Redis）跑起来
  2. 理解四种网络模式，掌握自定义网络实现容器互访
  3. 数据卷解决持久化，明白 bind mount 和 named volume 的取舍
  4. 会写 Dockerfile 给自己的应用打镜像，用多阶段构建控制镜像体积
  5. 最后用 Compose 编排整套应用栈，一键起环境

到这个程度，日常开发和测试环境的容器化需求就够用了。
