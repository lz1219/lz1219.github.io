PostgreSQL 实战手册（三）：视图与常用函数精讲

系列第三篇。延续 shop 演示库（users / products / orders / order_items），基于 PostgreSQL 16。

系列目录：一、基础命令与日常管理 ｜ 二、函数与存储过程 ｜ 三、视图与常用函数精讲 ｜ 四、性能分析与 SQL 调优 ｜ 五、事务、MVCC 与锁

一、视图：不只是”保存的查询”

1.1 普通视图

PG 的普通视图是规则重写：查询视图时优化器把视图定义展开进主查询一起规划，没有”视图临时表”这种东西，性能心智负担比想象小。

可更新视图：单表、无聚合/无 DISTINCT/无窗口函数、含全部 NOT NULL 列的简单视图，可以直接 INSERT/UPDATE/DELETE，操作会透传到基表：

1.2 物化视图：把结果落盘

MySQL 没有物化视图（只能用汇总表 + 定时任务手搓），这是 PG 报表场景的标配武器。代价：数据是快照，刷新前是旧数据，刷新策略（定时 pg_cron / 触发 / 应用触发）要自己设计。

四、类型转换

注意隐式转换纪律：PG 比 MySQL 严格得多，WHERE varchar_col = 123 在 PG 里直接报错，不会帮你隐式转。这是好事——MySQL 的隐式转换是索引失效和数据错误的温床。

五、聚合进阶

GROUP_CONCAT 在 MySQL 里有默认 1024 字节截断的坑；string_agg 没有这种隐藏截断。

六、窗口函数实战

窗口函数对已分组/过滤后的结果集再做一层”行间计算”，行数不减少——这是它与 GROUP BY 的本质区别。

窗口函数不能写在 WHERE 里（它在 WHERE 之后才计算），要按窗口结果过滤必须套子查询，上面的”最近一次订单”就是标准模板。

七、JSONB：PG 的招牌

products.attrs 是 JSONB 类型（二进制存储、可索引、保留去重后的键），别用 TEXT 存 JSON。

对照 MySQL：->> 对应 JSON_UNQUOTE(JSON_EXTRACT(...)) 的 ->> 运算符（这个语法是 MySQL 学 PG 的）；但 JSON 路径查询、包含索引（GIN）的成熟度 PG 明显领先。

九、避坑指南：NULL 与时间的四个暗礁

  1. NULL 传染一切：NULL || 'abc' 是 NULL，NULL = NULL 不是 TRUE 是 NULL。拼接用 concat()（忽略 NULL），比较用 IS NOT DISTINCT FROM
  2. NOT IN (含 NULL 的子查询) 返回零行：x NOT IN (1, 2, NULL) 恒为 NULL。子查询先 WHERE col IS NOT NULL，或改用 NOT EXISTS
  3. now() 在事务里不动：长事务里分批写数据，所有行的 created_at DEFAULT now() 是同一个值——需要真实时间的用 clock_timestamp()，但先想清楚自己到底要哪种语义
  4. timestamp vs timestamptz：前者不带时区，跨时区系统必出诡异偏移。一律用 timestamptz

十、与 MySQL 函数对照速查

需求 MySQL 8 PostgreSQL 16
拼接 CONCAT / CONCAT_WS concat() / `
逗号串包含 FIND_IN_SET = ANY(string_to_array(...)) 或数组类型 @>
行转字符串 GROUP_CONCAT（有截断坑） string_agg(col, sep ORDER BY ...)
日期格式化 DATE_FORMAT(t, '%Y-%m-%d') to_char(t, 'YYYY-MM-DD')
当前时间 NOW()（语句开始） now()（事务开始！）
条件计数 SUM(IF(...)) / COUNT(CASE...) COUNT(*) FILTER (WHERE ...)
窗口函数 8.0 起支持 支持，帧子句更完整
JSON JSON 类型 + ->> JSONB + @> + GIN 索引
序列生成 无（递归 CTE 模拟） generate_series

总结

  • 普通视图是规则重写不是临时表；简单视图可直接更新，WITH CHECK OPTION 守住边界
  • 物化视图 + REFRESH ... CONCURRENTLY 是报表标配，唯一索引是并发刷新的前提
  • 三个”当前时间”语义不同：now() 随事务冻结，别混用
  • JSONB + GIN 让 PG 兼具文档库能力；->> 取值、@> 查询是日常两件套
  • generate_series + LEFT JOIN 解决一切”日期序列补零”报表
  • NULL 的三大暗礁：传染、NOT IN、拼接——对应武器是 concat()、IS NOT DISTINCT FROM、NOT EXISTS
