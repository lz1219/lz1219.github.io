Git 详解与命令大全

Git 是当下最流行的分布式版本控制系统。无论是个人项目还是团队协作，掌握 Git 的核心概念与常用命令，都是高效开发的必修课。本文从基础概念讲到高阶操作，重点覆盖“撤销 commit”的各种方式与常见工作场景，并附一份可收藏的命令速查表。

一、Git 核心概念

1.1 分布式版本控制

与 SVN 这类集中式版本控制不同，Git 在每个开发者的本地都保存一份完整的仓库副本（包括全部历史记录）。这意味着：

  • 提交、分支、回溯都可以在本地完成，无需联网。
  • 中央仓库（如 GitHub、GitLab）只用于同步与协作，不是工作必需。
  • 即使远端不可用，仍可继续开发，稍后再推送。

1.2 三个工作区域

Git 管理文件时，文件会在三个区域之间流转：

  • 工作区（Working Directory）：你看到的实际文件目录。
  • 暂存区（Staging Area / Index）：准备提交的改动快照，通过 git add 放入。
  • 版本库（Repository / HEAD）：git commit 后，改动正式成为历史记录。

1.3 四种对象类型

Git 底层只保存四类对象，理解它们有助于理解很多命令的行为：

  • Blob：保存文件内容。
  • Tree：保存目录结构（类似文件夹）。
  • Commit：保存一次提交，包含作者、时间、父提交和根 tree。
  • Tag：指向某个 commit 的引用，分为轻量标签和附注标签。

四、撤销与回退：完整方案

撤销是 Git 使用中最容易出错的地方。核心原则是：先判断改动在哪一个区域，再选择对应的命令。

4.1 撤销工作区改动

场景：文件已修改，但还没 git add，想放弃修改。

4.2 撤销暂存区改动

场景：已经 git add 了文件，但还没 git commit，想把文件撤出暂存区。

4.3 修改最后一次提交（未推送）

场景：刚 git commit 完，发现提交信息写错、漏了文件、或者想拆分提交。

注意：git commit --amend 会改变 commit hash。如果该提交已经 push 到远程共享分支，请改用 git revert，否则会让队友历史混乱。

4.4 回退已提交的 commit（本地）

git reset 用于移动当前分支指针，可以回退到某个历史版本。根据 --soft、--mixed、--hard 三种模式，对工作区和暂存区的影响不同。

模式 版本库（HEAD） 暂存区（Index） 工作区
--soft 回退 保留改动 保留改动
--mixed（默认） 回退 清空 保留改动
--hard 回退 清空 清空

4.5 回退已推送的 commit（安全方式）

如果 commit 已经 push 到远程共享分支，不要使用 git reset --hard，否则会让队友拉取时冲突。应使用 git revert，它会生成一个新的提交来“抵消”之前的改动，历史记录保持完整。

十一、常用命令速查表

命令 作用
git init 初始化仓库
git clone <url> 克隆远程仓库
git status 查看状态
git add <file> 添加文件到暂存区
git add . 添加当前目录改动
git commit -m "msg" 提交改动
git commit -am "msg" 对跟踪文件直接 add + commit
git commit --amend 修改最近一次提交
git push origin <branch> 推送到远程
git pull origin <branch> 拉取并合并
git fetch origin 拉取远程但不合并
git branch 查看分支
git branch -d <branch> 删除分支
git checkout -b <branch> 创建并切换分支
git switch -c <branch> 现代方式创建并切换分支
git merge <branch> 合并分支
git merge --abort 取消合并
git rebase <branch> 变基到目标分支
git rebase --abort 取消变基
git log --oneline 简洁查看提交历史
git log --oneline --graph 图形化查看历史
git diff 查看工作区与暂存区差异
git diff --cached 查看暂存区与版本库差异
git diff HEAD 查看工作区与最新提交差异
git show <hash> 查看某次提交详情
git stash 储藏当前改动
git stash pop 恢复并删除储藏
git stash list 查看储藏列表
git tag -a v1.0 -m "msg" 创建附注标签
git reset --soft HEAD~1 软回退上一次提交
git reset --mixed HEAD~1 混合回退上一次提交
git reset --hard HEAD~1 硬回退上一次提交（危险）
git revert <hash> 安全撤销某次提交
git reflog 查看操作历史
git restore <file> 恢复文件（Git 2.23+）
git restore --staged <file> 撤出暂存区
git remote -v 查看远程地址
git cherry-pick <hash> 挑选 commit 应用
git bisect start 启动二分查找
git rm --cached <file> 停止跟踪文件但保留本地
git push --force-with-lease 较安全的强制推送

总结

Git 的命令看似繁多，但只要抓住 工作区、暂存区、版本库 三个区域和 提交、分支、远程 三条主线，就能游刃有余。本文重点补充了撤销 commit 的完整方案：

  • 未提交时用 git restore / git reset HEAD；
  • 已提交未 push 时用 git commit --amend 或 git reset --soft；
  • 已 push 到共享分支时务必用 git revert；
  • 误删或误 reset 后用 git reflog 找回；
  • 团队分支强制推送前优先 git push --force-with-lease。

建议把速查表收藏，遇到不确定的命令再回来查；熟练之后，可进一步学习 .gitattributes、hooks、worktree 等高级特性，让 Git 真正为开发效率服务。
