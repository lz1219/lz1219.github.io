Kubernetes 核心概念与常用命令总结

上一篇总结了 Docker 单机容器的用法，但当容器数量变多、需要跨机器部署时，就需要编排系统了。Kubernetes（简称 K8s）是目前事实上的容器编排标准。本文梳理 K8s 的核心概念、架构和 kubectl 常用命令，作为入门和速查手册。

一、K8s 是什么，解决什么问题

Docker 解决了”如何把应用打包运行”的问题，但在生产环境还会遇到：

  • 容器挂了谁来重启？流量大了如何扩容？
  • 多台机器上容器如何调度、如何互相发现？
  • 如何滚动更新而不停机？

K8s 就是为解决这些问题而生的：它把一批机器组成集群，你声明”我要 3 个 Nginx 副本”，它负责调度、保活、扩缩容和自愈。

二、集群架构

一个 K8s 集群分为两部分：

控制平面（Control Plane）：集群的大脑

组件 作用
kube-apiserver 集群唯一入口，所有操作都通过它的 REST API
etcd 分布式键值存储，保存集群全部状态
kube-scheduler 调度器，决定 Pod 跑在哪个节点
kube-controller-manager 控制器集合，负责让实际状态逼近期望状态

工作节点（Node）：跑容器的机器

组件 作用
kubelet 节点代理，负责启动/监控本节点的 Pod
kube-proxy 网络代理，实现 Service 的负载均衡
容器运行时 containerd / CRI-O（1.24 起不再直接支持 Docker）

你的操作链路：kubectl → apiserver → 写入 etcd → 调度器和控制器协调 → kubelet 在节点上拉起容器。

三、核心概念

3.1 Pod：最小部署单元

K8s 不直接操作容器，而是操作 Pod。一个 Pod 可包含一个或多个共享网络和存储的容器（绝大多数情况是一个）。同一 Pod 内容器通过 localhost 通信——这就是 Docker 网络模式里 container 模式的应用。

不要单独创建 Pod，Pod 是”一次性”的，挂了不会自动重建。实际工作都用下面的工作负载资源管理 Pod。

3.2 Deployment：无状态应用的标准用法

管理一组相同的 Pod 副本，负责：

  • 副本保活：Pod 挂了自动重建，节点挂了自动迁移
  • 滚动更新：逐个替换旧版本 Pod，服务不中断
  • 回滚：更新出问题一键退回上个版本

3.3 Service：稳定的访问入口

Pod 重建后 IP 会变，不能直接访问。Service 给一组 Pod 提供固定虚拟 IP 和 DNS 名，并做负载均衡。通过 label selector 关联 Pod。

四种类型：

类型 作用 场景
ClusterIP（默认） 仅集群内部可访问 服务间调用，如 app 访问 mysql
NodePort 每个节点开一个端口（30000-32767）对外暴露 测试环境简单暴露
LoadBalancer 向云厂商申请负载均衡器 云上生产环境对外服务
ExternalName 返回 CNAME 别名 引用集群外部服务

集群内其他服务通过 http://myapp-svc 即可访问（DNS 自动解析）。

3.4 其他常用工作负载

资源 用途
StatefulSet 有状态应用：固定名称、固定存储、有序启停（MySQL、Redis、Kafka）
DaemonSet 每个节点跑一个副本（日志采集、监控 agent）
Job 一次性任务，跑完即结束
CronJob 定时任务（crontab 语法）

3.5 Namespace：逻辑隔离

把集群划分成多个虚拟空间，用于环境隔离（dev/test/prod）或团队隔离。常用自带命名空间：default、kube-system（系统组件）、kube-public。

3.6 ConfigMap 与 Secret：配置与镜像分离

在 Deployment 里以环境变量或文件挂载方式注入容器。

3.7 Ingress：七层流量入口

Service（NodePort/LoadBalancer）是四层暴露，Ingress 提供七层能力：按域名和路径路由、HTTPS 终止、虚拟主机。一个 Ingress 可以把 api.example.com 和 web.example.com 路由到不同 Service，是生产环境的标准入口。

五、YAML 声明式管理

K8s 的哲学是声明式：你描述期望状态（YAML），控制器负责达成。所有资源 YAML 都有四个顶层字段：

记不住字段就用 kubectl explain <resource>.<field> 查，比翻文档快。

六、本地学习环境

入门不用搭真集群：

  • minikube：官方单节点本地集群，minikube start 一条命令搞定
  • kind（Kubernetes in Docker）：用 Docker 容器跑 K8s 节点，轻量快速，适合 CI
  • Docker Desktop：自带单节点 K8s，设置里勾选即可开启

总结

推荐的学习路径：

  1. 先吃透 Pod / Deployment / Service 三件套，这是 80% 场景的核心
  2. 用 minikube 或 kind 起一个本地集群，把一个 Docker 化的应用部署上去
  3. 熟练 get / describe / logs / exec 排障四板斧
  4. 再按需了解 StatefulSet（有状态）、Ingress（流量入口）、ConfigMap/Secret（配置管理）
  5. 最后才是 Helm（包管理）、HPA（自动扩缩容）、RBAC（权限）这些进阶主题

K8s 概念多，但主线很清晰：一切都是”声明期望状态，控制器负责实现”，抓住这条主线，剩下的都是查表的事。
