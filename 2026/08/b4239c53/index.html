PostgreSQL 实战手册（一）：基础命令与日常管理

这是 PostgreSQL 实战手册系列的第一篇，面向日常开发与运维场景。全系列基于 PostgreSQL 16，共用一个演示库 shop，示例均可直接复制执行。因为读者大多有 MySQL 背景，每篇末尾附与 MySQL 的关键差异对照。

系列目录：一、基础命令与日常管理 ｜ 二、函数与存储过程 ｜ 三、视图与常用函数精讲 ｜ 四、性能分析与 SQL 调优 ｜ 五、事务、MVCC 与锁

〇、准备演示环境

注意 GENERATED ALWAYS AS IDENTITY——这是 SQL 标准自增列写法，比老的 SERIAL 更可控（SERIAL 本质是”帮你建一个 sequence + 默认值”的语法糖，权限和语义都有坑，见下文避坑）。

一、psql 元命令：效率的核心

psql 里以反斜杠开头的是客户端元命令，不是 SQL，不发给服务器解析。最常用的：

命令 作用 MySQL 对应
\l 列出所有数据库 SHOW DATABASES
\c shop 切换数据库 USE shop
\dt 列出当前 schema 的表 SHOW TABLES
\d users 查看表结构（含索引、约束、触发器） DESC users
\di / \dv 只列索引 / 只列视图 -
\du 列出角色（用户） SELECT user FROM mysql.user
\x 切换竖排显示（宽行神器） \G
\timing 开关执行耗时显示 默认开启
\e 用编辑器写 SQL，保存即执行 edit
\watch 2 每 2 秒重复执行上一条 SQL（监控用） 无
\? / \h SELECT 元命令帮助 / SQL 语法帮助 help

\d users 的输出远比 DESC 丰富：列、默认值、索引、外键引用与被引用、约束、触发器一屏全出，是日常排查的第一入口。

二、表结构操作（DDL）

PG 的 DDL 有两个 MySQL 用户会不适应的特性：

  1. DDL 是事务性的：ALTER TABLE 可以放在事务里，出错整体回滚，不会出现”改了一半”的表。MySQL 的 DDL 会隐式提交，做不到这点
  2. 加带默认值的列是 O(1)：PG 11 起 ADD COLUMN ... DEFAULT x NOT NULL 不再重写整张表，只记元数据。MySQL 大表加列仍是昂贵的表重建

SCHEMA 的概念：PG 里数据库 > schema > 表，默认 schema 是 public，跨库查询不行（要用 dblink/FDW），但跨 schema 查询天然支持。MySQL 的 schema 就是 database 的同义词，别混淆。

三、数据操作（DML）

RETURNING 是 PG 的杀手级特性：写操作和结果确认一次网络往返完成，应用层不再需要”先写后查”。

避坑指南：从 MySQL 过来最容易踩的四个坑

  1. 标识符大小写折叠：PG 把未加双引号的标识符折叠成小写，CREATE TABLE UserInfo 实际建成 userinfo；一旦用双引号建成 "UserInfo"，此后每次访问都必须带双引号且区分大小写。结论：永远用全小写蛇形命名，永远不要加双引号
  2. 布尔是真布尔：WHERE is_active 直接写，is_active = 1 会报错。TRUE/FALSE 是一等公民，不是 tinyint 的马甲
  3. 空串不是 NULL：PG 里 '' 和 NULL 严格区分（Oracle 是合并的，MySQL 兼容两种写法），concat() 对 NULL 的处理与 || 运算符不同——'a' || NULL 得 NULL，concat('a', NULL) 得 'a'
  4. SERIAL 的坑：SERIAL 列如果显式插入 id，sequence 不会跟着推进，后续自增会撞主键。用 IDENTITY 列配合 GENERATED BY DEFAULT + 手动 setval() 修正，或直接避免混插

避坑指南：权限三大高频事故

  1. GRANT 只作用于现有对象——新表建完应用报 permission denied，十有八九是忘了 ALTER DEFAULT PRIVILEGES
  2. PG 15 起 public schema 收紧：默认不再给所有用户写权限，老脚本直接 CREATE TABLE 会失败，需要显式 GRANT CREATE ON SCHEMA public
  3. 权限是按对象属主语境的：函数默认以调用者权限执行（SECURITY INVOKER），需要提权执行时显式声明 SECURITY DEFINER——这也是注入风险点，第二篇细讲

六、备份与恢复

pg_dump 逻辑备份（最常用）

避坑指南：备份的四个真相

  1. pg_dump 自带一致性快照：单库备份内部是一个事务快照，不需要锁全库，但多个 pg_dump 分别备份的库之间没有一致性
  2. 客户端版本要 ≥ 服务器版本：用 PG 14 的 pg_dump 导 PG 16 的库会失败，反过来可以
  3. 逻辑备份 ≠ 时间点恢复（PITR）：要做到”恢复到误删前一分钟”，需要开启 WAL 归档 + 基础备份（pg_basebackup），这是物理备份体系，日常用 pg_dump，容灾用 WAL
  4. 大对象（BLOB）不在默认导出里，需要 -b 参数

八、批量数据导入导出：COPY

COPY 是 PG 里最快的批量通道（比逐条 INSERT 快一个数量级），相当于 MySQL 的 LOAD DATA INFILE，但权限模型友好得多。

九、与 MySQL 的关键差异对照

维度 MySQL 8 PostgreSQL 16
自增列 AUTO_INCREMENT GENERATED ... AS IDENTITY（推荐）/ SERIAL（遗留）
层级 database = schema database > schema > table
upsert ON DUPLICATE KEY UPDATE ON CONFLICT (...) DO UPDATE
写操作返回 无（需再查） RETURNING 子句
DDL 事务 隐式提交，不可回滚 可回滚
备份热一致 mysqldump 需 --single-transaction（仅 InnoDB） pg_dump 天然快照一致
批量导入 LOAD DATA INFILE（权限麻烦） COPY / \copy
查看会话 SHOW PROCESSLIST pg_stat_activity

总结

  • psql 元命令（\dt、\d、\x、\watch）是日常效率核心，\d 表名 信息密度远超 DESC
  • DDL 可回滚、加带默认值列是 O(1)，这两件事改变你对表变更的恐惧程度
  • RETURNING 让写操作一次往返拿到结果；ON CONFLICT 是比 MySQL 更严谨的 upsert
  • 权限三件套：GRANT + ALTER DEFAULT PRIVILEGES + 记住 PG 15 的 public schema 收紧
  • 备份日常用 pg_dump -Fc + pg_restore -j，容灾上 WAL 归档 + pg_basebackup
  • 命名全小写蛇形、布尔当布尔用、'' ≠ NULL——从 MySQL 迁移先过这三关
