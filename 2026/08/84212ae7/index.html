系列目录：一、基础命令与日常管理 ｜ 二、函数与存储过程 ｜ 三、视图与常用函数精讲 ｜ 四、性能分析与 SQL 调优 ｜ 五、事务、MVCC 与锁

〇、先厘清：PG 的函数体系与 MySQL 的本质差异

MySQL 里”存储过程”和”函数”是两个相似的东西，都能在 CALL 或 SQL 里用。PG 则是严格分工：

CREATE FUNCTION CREATE PROCEDURE（PG 11+）
调用方式 在 SQL 里：SELECT f(x) 单独调用：CALL p(x)
返回值 必须有 没有（靠 INOUT 参数带出）
事务控制 不允许 COMMIT/ROLLBACK 可以 COMMIT/ROLLBACK
典型用途 计算、转换、返回结果集 批处理、分阶段提交的长任务

另外一个压倒性的差异：PG 的函数体可以用多种语言写——SQL、PL/pgSQL（内置）、PL/Python、PL/Perl 等。本篇只用内置的 SQL 和 PL/pgSQL。

一、SQL 函数：最简单也最容易被低估

SQL 函数的关键优势：满足条件的单条 SQL 函数可以被优化器内联（inlining），展开进外层查询一起规划，性能往往好于 PL/pgSQL 版本。能用一个 SQL 写完的逻辑，就不要上 PL/pgSQL。

$$ ... $$ 是 PG 的美元引用字符串（dollar quoting），函数体写在里面，不需要像 MySQL 那样 DELIMITER // 改分隔符。

二、PL/pgSQL 函数：结构骨架

骨架四段：DECLARE（可省）→ BEGIN ... END → 语句以分号结尾 → $$ 包裹。赋值用 :=，SQL 结果入变量用 SELECT ... INTO var。

三、参数模式与返回结果集

3.1 IN / OUT / INOUT

3.2 RETURNS TABLE / SETOF：返回多行

与 MySQL 的对比要划重点：MySQL 存储过程返回结果集靠过程中的 SELECT 直接吐给客户端，调用方无法再加工；PG 的表函数返回的是一等公民关系，可以继续 WHERE、JOIN、聚合——这才是”可组合的存储逻辑”。

四、流程控制

五、异常处理

两个必须知道的语义：

  1. EXCEPTION 块的代价：PG 的异常捕获内部用子事务（savepoint）实现，进入带 EXCEPTION 的块就有开销，高频小函数里滥用会拖慢性能
  2. 吃掉异常 ≠ 回滚整单：WHEN OTHERS THEN RETURN FALSE 只回滚到块入口的子事务点，块外已做的修改还在——这正是它危险的地方，日志一定要留下

六、存储过程：为事务控制而生

PROCEDURE 的存在理由只有一个：在过程体内 COMMIT/ROLLBACK，把巨型批任务切成小事务，避免长事务占锁、撑爆 WAL。限制也随之而来：带事务控制的过程只能在顶层 CALL，不能在被事务包裹的调用链里用。

七、触发器函数：自动化的最后一环

触发器函数里 NEW / OLD 代表新/旧行；BEFORE 行级触发器 RETURN NULL 可阻止本次写入，AFTER 触发器的返回值会被忽略（习惯仍写 RETURN NEW）。克制使用：触发器是隐式逻辑，排查问题时最难想到的地方，能写进应用层的别藏进触发器。

八、避坑指南

  1. 函数里不能 COMMIT——只有 PROCEDURE 能；函数内尝试事务控制直接报错
  2. SECURITY DEFINER 是双刃剑：函数以属主权限执行，能优雅实现”受控提权”，但函数体内拼接动态 SQL 时就是注入跳板，务必用 EXECUTE ... USING $1 参数化，别用字符串拼接
  3. 标注挥发性的实际影响：IMMUTABLE（同参数恒同结果）的函数可用于表达式索引和被优化器常量折叠；VOLATILE（默认）的函数会阻止一堆优化。标错 IMMUTABLE 是静默数据错误，标漏是性能损失
  4. SELECT ... INTO 多行时只取第一行且不报错——要么 LIMIT 1 明确意图，要么用 STRICT（SELECT ... INTO STRICT）让它在多行/零行时抛异常
  5. MySQL 的 DELIMITER 习惯忘掉：PG 用 $$，函数体内的分号不会结束定义

九、与 MySQL 存储过程对照

维度 MySQL 8 PostgreSQL 16
分隔符 需 DELIMITER // 美元引用 $$，无需改分隔符
返回结果集 过程中 SELECT 直吐客户端 表函数 RETURNS TABLE，可继续参与查询
事务控制 过程里可 COMMIT 仅 PROCEDURE 可，函数严格禁止
异常处理 DECLARE ... HANDLER BEGIN ... EXCEPTION WHEN，基于子事务
函数语言 仅 SQL 过程语言 SQL、PL/pgSQL、PL/Python 等可扩展
表达式索引 8.0.13+ 支持 functional key parts IMMUTABLE 函数可建表达式索引

总结

  • 能用单条 SQL 写完的用 SQL 函数（可内联），需要逻辑再上 PL/pgSQL
  • 返回结果集用 RETURNS TABLE，它是可继续加工的一等关系，远优于 MySQL 的”过程吐结果”
  • PROCEDURE 的存在理由只有一个：过程体内分阶段 COMMIT
  • 异常捕获有子事务开销，高频路径慎用；吃异常必须留日志
  • SECURITY DEFINER + 动态 SQL 是注入重灾区，EXECUTE ... USING 参数化是底线
