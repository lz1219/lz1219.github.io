MySQL 实战手册（一）：基础命令与日常管理

这是 MySQL 实战手册系列的第一篇，面向日常开发与运维场景。全系列基于 MySQL 8.0，共用同一个演示库 shop，示例均可直接复制执行。

系列目录：一、基础命令与日常管理 ｜ 二、存储过程与自定义函数 ｜ 三、视图与常用函数精讲 ｜ 四、性能分析与 SQL 调优 ｜ 五、事务与锁

〇、准备演示环境

建表规范（来自生产经验）：主键用 BIGINT UNSIGNED AUTO_INCREMENT；字符集一律 utf8mb4（utf8 是残缺的 3 字节编码，存不了 emoji）；时间用 DATETIME 而非 TIMESTAMP（后者有 2038 年问题和时区隐式转换）；字段尽量 NOT NULL。

二、表结构操作（DDL）

大表变更注意事项：MySQL 8.0 对加列等操作支持 ALGORITHM=INSTANT（秒级完成），但改列类型、删列仍需重建表。生产大表（千万级以上）变更建议：

先在同款从库上验证耗时，再上生产；超大表考虑 pt-online-schema-change 或 gh-ost。

三、数据操作（DML）

避坑指南：DML 三大事故根源

  1. UPDATE/DELETE 忘写 WHERE：养成”先 SELECT 同条件、再改写为 UPDATE/DELETE”的肌肉记忆；可开启安全模式 SET sql_safe_updates = 1;（不带索引条件的 UPDATE/DELETE 直接报错）
  2. DELETE 与 TRUNCATE 混用：DELETE 逐行删除、记 binlog、可回滚、不重置自增；TRUNCATE 是 DDL，瞬间清空但不可回滚
  3. 隐式类型转换：WHERE user_id = '123abc' 会截断成 123 匹配成功，脏数据就这么进来了

四、索引管理

联合索引最左前缀原则：索引 (a, b, c) 能服务 a、a,b、a,b,c 的查询，但服务不了跳过 a 直接查 b 的场景。列顺序经验法则：等值查询列在前，范围/排序列在后。

注意：二级索引叶子节点自动携带主键值，所以主键别太大，避免所有索引跟着膨胀。

五、用户与权限

避坑指南：权限三大陋习

  1. 应用直连 root：一旦 SQL 注入就是全库沦陷，必须独立账号 + 最小权限
  2. GRANT ALL ON *.*：权限放大器，等于把 root 批发出去
  3. 给应用账号 DDL 权限：应用不应该能 DROP TABLE，DDL 走变更流程执行

MySQL 8.0 中 GRANT 语句自动刷新权限，不再需要 FLUSH PRIVILEGES（只有直接改 mysql.user 表才需要）。

六、备份与恢复

mysqldump 逻辑备份（最常用）

关键参数说明：

参数 作用
--single-transaction InnoDB 热备核心：开启一致性快照，备份期间不阻塞读写
--routines --triggers 连存储过程和触发器一起备份（默认不含！）
--master-data=2 记录 binlog 位点（搭建从库时用）

避坑指南：备份的四个真相

  1. 不加 --single-transaction 的 InnoDB 备份会锁表，高峰期能把业务锁死
  2. 不加 --routines，存储过程和函数会静默丢失（下一篇的主角，别在这儿弄丢了）
  3. mysqldump 是逻辑备份，恢复速度远慢于备份速度；百 GB 级库建议用物理备份工具（Percona XtraBackup）
  4. 备份不演练等于没备份：定期恢复到测试环境验证可用性；需要精确到时间点的恢复，必须配合 binlog

七、日常管理命令速查

排查和巡检时最常用的一组命令：

SHOW TABLE STATUS 里重点看 Data_length + Index_length（表多大）和 Data_free（碎片，过大且表更新频繁时可 OPTIMIZE TABLE 回收，注意它会锁表重建，低峰执行）。

八、批量数据导入导出

注意事项：受 secure_file_priv 参数限制，文件只能放在指定目录（SHOW VARIABLES LIKE 'secure_file_priv' 查看）；客户端侧导入用 LOAD DATA LOCAL INFILE（需客户端和服务端都开启 local_infile）。大数据量迁移时，LOAD DATA 是 mysqldump 之外的重要选项。

九、binlog 与时间点恢复（PITR）

mysqldump 是”全量快照”，误删数据想精确恢复到删除前一刻，靠的是 binlog（记录所有数据变更的二进制日志，也是主从复制的基础）：

避坑：恢复务必先在测试库演练，确认 stop-position 恰好卡在误操作 SQL 之前一条；生产恢复流程是”恢复全量到临时库 → 重放 binlog 到误删前 → 导回误删的数据”，不是直接在原库上重放。

总结

本篇覆盖了日常最高频的操作：库表管理、DML、索引、权限、备份。记住三条军规：变更前备份、DML 先 SELECT、权限最小化。
